# VSingerXrossPlayer

「歌ってみた」動画を楽しむための、PSP XMB（クロスメディアバー）風Webアプリケーションです。
歌手ごとの歌唱動画と原曲情報を収集し、選曲の共通度から近い歌手を可視化します。

公開サイト: [https://v-singer-xross-player.vercel.app](https://v-singer-xross-player.vercel.app)

## 特徴

- **XMB風ナビゲーション**: 矢印キーによる直感的な操作（上下左右）。
- **AI特徴可視化**: 歌い手や楽曲の「Energy」「Mood」「Vocal」「Instrumental」をレーダーチャートで表示。
- **背景動画再生**: 選択中の楽曲を背景でループ再生。

## 検索と絞り込み

画面上部で曲名・歌い手・原曲アーティストを検索できます。歌い手や原曲アーティストの所属・ユニット・レーベルタグと、原曲アーティスト名で絞り込めます。XMBの表示単位は「楽曲ごと」「原曲アーティストごと」「歌い手ごと」から選べます。絞り込みは各表示に適用されます。

歌い手の所属・ユニット・別名とユニット名から個人名への対応、原曲アーティストのタグは `public/singer-metadata.json` で管理します。このファイルは収集データを更新しても保持されます。ユニット名で登録された歌唱は、対応表に記載されたメンバーそれぞれの一覧に表示されます。原曲アーティストのグルーピングは動画データの `original_artist_name` を使います。

原曲アーティスト名に確認済みの合成音声名が独立した名義として付いている場合は、画面表示・絞り込み・類似マップでその名義を除いて集約します。たとえば `カンザキイオリ / 鏡音リン / 鏡音レン` は `カンザキイオリ` として扱います。確認済みの名前は `src/utils/singerSimilarity.ts` に列挙し、曖昧な名義は残します。収集元の原曲クレジットと原曲IDは変更しません。

[音楽的同位体の公式製品一覧](https://musical-isotope.kamitsubaki.jp/product/)に載る可不・星界・裏命・狐子・羽累も確認済みの合成音声名です。「世界」は「星界」とは別の表記として扱います。歌い手として登録された音楽的同位体には「KAMITSUBAKI STUDIO」と「音楽的同位体」のタグを付けます。

所属とメンバーの確認元: [にじさんじ公式](https://www.nijisanji.jp/)、[RK Music](https://rkmusic.jp/artist/316/)、[HOLOSTARS公式](https://holostars.hololivepro.com/en/talent/)、[ホロライブ公式](https://hololive.hololivepro.com/talents/hoshimachi-suisei/)、[KAMITSUBAKI STUDIO](https://kamitsubaki.jp/artist/kaf/)。

## 動作環境

- Node.js (v18以上推奨)
- npm

## 起動方法

### 1. インストール

プロジェクトのルートディレクトリで以下のコマンドを実行し、依存関係をインストールします。

```bash
npm install
```

### 2. 開発サーバーの起動

以下のコマンドでローカル開発サーバーを起動します。

```bash
npm run dev
```

ブラウザで `http://localhost:5173` (または表示されるURL) にアクセスしてください。

### 3. ビルド

本番用にビルドする場合は以下のコマンドを実行します。

```bash
npm run build
```

生成されたファイルは `dist` ディレクトリに出力されます。

## 操作方法

- **↑ / ↓**: アイテム（歌い手、楽曲など）の選択
- **← / →**: カテゴリ（Singers, Songs, Settings）の切り替え

## 選曲が近い歌手を探す

トップビューの「縦横を転置」ボタンで、「楽曲ごとにカバー歌手を見る」表示と「歌手ごとに楽曲を見る」表示を切り替えられます。コラボ曲は参加歌手全員の一覧に含まれます。

画面右上の「選曲類似マップ」から、全歌手を選曲類似度に基づく2次元マップで確認できます。ダイアログ内のボタンで「歌手 → 楽曲 → 原曲アーティスト」を切り替えられます。楽曲モードでは同じ歌手に歌われている曲、原曲アーティストモードでは同じ歌手にカバーされているアーティストを近くに配置します。点を選ぶと類似する上位5件を線と一覧で表示します。マップの軸や方向に意味はなく、正確な比較には一覧の類似度を使います。

- APIの `original_song_id` を優先して原曲を照合します。IDがない場合は、原曲対応表、曲名＋原曲アーティストの順で照合します。曲名は `original_song_title`、なければ `song_title` を使い、動画タイトルへのフォールバックは行いません。
- 曲名とアーティストのNFKC・前後空白・連続空白・英字大小文字を正規化します。アーティスト不明の曲は「曲名のみの暫定照合」と表示し、原曲特定済みの曲とは統合しません。
- `singers` の全参加者に曲を割り当て、同じ歌手の同曲の複数投稿は1曲として集計します。
- 原曲の有無に `log((1 + 歌手数) / (1 + その曲を歌う歌手数)) + 1` の重みを付け、コサイン類似度を計算します。歌手数は比較可能な登録曲を持つ歌手の数です。
- 原曲アーティストについても選曲数と希少性を重み付けしたコサイン類似度を計算し、完全一致の曲による類似度で説明されていない部分を最大25%まで補完します。
- スコアは曲調や声質の近さ、推薦の確率を表すものではありません。登録曲が3曲未満の場合は参考値として表示します。
- 同名異曲は原曲IDまたは原曲アーティストで区別します。両方が不明な場合の同名異曲は区別できません。比較対象は `/video-pages` で取得した全ページです。ページをまたぐ同一動画のコラボ参加者も統合します。バックエンドも同時に更新してください。

`npm test` で類似度計算のテストを実行します（Node.js標準テストランナー使用）。

### 原曲対応表

`public/original-songs.json` に確認済みの原曲を登録すると、既存DBを書き換えずに別名を統合できます。初期値は空配列です。以下は形式を示す架空の例です。

```json
[
  {
    "id": "original-0001",
    "title": "正式な曲名",
    "artist": "原曲アーティスト",
    "aliases": [{ "title": "別表記の曲名", "artist": "原作者の別表記" }],
    "videoIds": ["確認済みのカバー動画ID"]
  }
]
```

- `id` は原曲単位で固定し、名称の修正時も変更しません。APIの `original_song_id` と同じIDを使用します。
- 正式な曲名とアーティストの組も自動的に照合対象になります。別名には原曲アーティストを必ず指定します。
- `videoIds` は原曲を確認済みの**カバー動画**を指定します。原曲アーティスト未登録の動画も確実に割り当てられます。
- APIの明示的なIDを最優先し、IDがなければ動画ID対応、曲名＋原曲アーティストの別名対応の順に照合します。
- ID重複や、同じ別名・動画を複数の原曲へ割り当てた対応表は読み込みエラーになります。
- バックエンドはDynamoDBの任意属性 `original_song_id` を返します。コレクターの `upsert_singer_video_index` は同名の任意引数を受け付けます。コレクターはWeb検索で特定した正式名と原曲アーティストからメタデータ由来のIDを生成し、確認済み対応表のIDを優先します。既存DBの一括更新は自動実行しません。

バックエンドの開発依存導入後（`cd backend && uv sync --extra dev`）、リポジトリルートから `uv run --project backend --extra dev python -m unittest discover -s backend/tests -v` で原曲情報のAPI変換テストを実行できます。外部DBへの接続は不要です。

収集は `vsxp-register-channel` でチャンネルを登録し、引数なしの `vsxp-collect` で登録済みチャンネルの未確認動画を処理する2段階です。準備・Web grounding・原曲ID付与・再試行は [collector/README.md](collector/README.md) を参照してください。`GEMINI_MODEL` と `ORIGINAL_SONGS_PATH` はコレクター用の追加設定です。設定例は `collector/.env.example` にあります。

既定では、コレクターが生成する `public/data/videos.json` と `public/data/singers.json` を画面から直接読みます。個人開発や検証ではAWS認証や常設バックエンドは不要です。定期収集をクラウドで動かす場合は、保存先をDynamoDBへ切り替えられます。
